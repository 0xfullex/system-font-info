# ts

The JS half of the package, compiled by `tsc` to `../dist` (CommonJS, with declarations; `npm run build:ts` empties it first, so output of deleted sources never ships). `types.ts` is the public type contract and is never edited as a side effect of other work. `../test/types/` holds its type-level tests (a separate TypeScript project, compiled by `npm run typecheck` and never run: `npm test` runs `../test/*.test.mjs` only, because a bare `node --test` would also execute the `.test.ts` files, which only declare calls for the compiler).

## Files

| File | Role |
| --- | --- |
| `types.ts` | Public types: the complete shapes (`FontFamily`, `FontFace`, `LanguageCoverage`, `OpenTypeInfo` and its tables, `DarwinNative`, `Win32Native`, `LinuxNative`) and the selection types (`Preset`, `Field`, `GetFamiliesOptions`, `GetFamilyOptions`, `SelectedFamily`, `SelectedFace`) that compute a result type from the options. The selection types sit between `// #region selection-types` and `// #endregion`; that text is the "Result typing" code block of `docs/api.md`, and the two stay identical. |
| `field-catalogue.ts` | `FIELD_CATALOGUE`: every field name with its level, smallest preset, identity flag, `opentype` tables and per-platform source: groups of OS work, `constant`, or `derivedFrom` (the package computes the field from other fields on that platform; derivation is per platform because a platform may get the same field from the OS). The one source of field facts: `../scripts/gen-fields.mjs` generates `../src/core/field_catalogue.h` and the generated regions of `../docs/api.md` and `../docs/platforms.md` from it, and `../test/types/catalogue.test.ts` asserts that its names are exactly `Field` and its presets exactly `PresetFields`. |
| `field-closure.ts` | `closureOf(selected, platform)`: the fields a call fetches on a platform (selected, plus the face identity when a `faces.*` field is selected, plus the inputs of derived fields transitively, minus the derived fields themselves), and `groupsOf(closure, platform)`: the groups of OS work that costs. Also `PRESETS` (smallest first) with `presetFields(preset)` (what each preset contains: the one home of that expansion) and `specOf(field)` (the one catalogue lookup, also used by `project.ts`). The one home of the closure rule: the request builder calls it, and `../scripts/gen-fields.mjs` calls it to generate the table of groups each preset reaches. `../test/catalogue.test.mjs` tests it. |
| `native.ts` | The internal contract with the addon: `NativeRequest` (the closure's field names, `families`, the resolved orthography names), the raw shapes it returns (`RawFamily`, `RawFace`, `RawAxis`, all keys optional because a result holds only the requested keys), the binding interface (`getFamilies`, `orthographies`, `__testing`), and the loader (`loadNative`; `loadBinding` takes the platform, architecture, libc and `require` as parameters, for tests). |
| `targets.ts` | `TARGETS`: the one table of the targets that ship a prebuilt addon (id, which is also the directory under `prebuilds/`, platform, architecture, libc on Linux, CI runner, whether the tests run there), with `findTarget`, `targetName` and `detectLibc`. `../scripts/targets.mjs --matrix` prints it as the CI matrix and `../scripts/copy-prebuild.mjs` names the directory from it. |
| `request.ts` | `buildRequest`: validates the options as the error table of `../docs/api.md` lists (every error here is a `TypeError`), joins `fields` with the preset's fields (`presetFields`), and computes the closure (`closureOf`) and the selected fields the platform derives (selected minus closure). Touches no addon. |
| `language-coverage.ts` | `resolveOrthography`: a `languageCoverage` tag to an fc-lang name (steps 0, a, b, c of `../docs/api.md`; a `RangeError` naming the tag when it is malformed or unresolved), with the names passed in; `resolveTags` for the option; `coverageEntries` assembles a family's `LanguageCoverage[]` from the addon's counts. |
| `normalize.ts` | `normalizeFamilies`: raw native result to the public shapes, for the keys present. Derives the family fields and the face `fullName`/`styleName` only for the fields the platform derives and the caller selected. Language tags of the public language fields (face and family `supportedLanguages`, every localized string's `language` including the `platform` ones) go through `canonicalizeLanguageTag`, which writes a bare four-letter script tag (`Latn`) as `und-Latn` on every platform; the `opentype.meta` `dlng`/`slng` tags are canonicalized without that and keep a bare script as written. |
| `project.ts` | `projectFamilies`: removes what was fetched only to derive something (closure minus selection, identity excepted) and `faces` when no face field is selected. |
| `list-families.ts` | `listFamilies`: the pipeline behind `getFamilies` and `getFamily`, with the addon and platform injectable for tests: validate, load the addon, resolve the `languageCoverage` tags (a `RangeError` comes after loading, because the orthography names are the addon's), call the addon, normalize and sort, assemble `languageCoverage`, project. |
| `pick-name.ts` | `pickName`: choose a localized string for an ordered list of locales. |
| `index.ts` | The public entry: `getFamilies`, `getFamily`, `pickName`, and all public types. |

## Invariants

- **The addon is loaded lazily**, on the first call that passes option validation. `normalize.ts` and `pick-name.ts` never import the loader, so they can be tested without a binary; `list-families.ts` takes the binding as a parameter for the same reason.
- **One prebuilt directory per target, one literal `require` per target.** The loader picks the target from `process.platform`, `process.arch` and, on Linux, the libc (glibc when Node's diagnostic report names a glibc version, else musl; detected once per process), and requires `../prebuilds/<id>/system-font-info.node`, with `<id>` = `<platform>-<arch>`, plus `-glibc` on Linux. The `switch` in `native.ts` writes every path as a string literal so bundlers can trace and include it; the compiler checks that its cases cover `TargetId`, and `../test/native.test.mjs` checks that they are the table's targets. If that fails, or no target matches, it falls back to `build/Release/system-font-info.node` for local builds. Failing all of them throws an error that lists each path with its failure. Specific messages: musl is not supported yet (there is no musl target), and on Linux a missing `libfontconfig.so.1` or `libfreetype.so.6` names the package to install. A new target is a row in `targets.ts` and a case in the `switch`.
- **Normalization mutates in place.** Faces that share an `opentype` or `axes` object in the native result share it afterwards, so each shared object is processed once (tracked with a `WeakSet`). Do not clone.
- **Canonicalize, then merge.** Every language tag goes through `Intl.getCanonicalLocales`, one tag at a time and cached; `""` stays `""`, a tag Intl rejects is kept as written. After that, localized arrays merge exact `(language, value)` duplicates and string arrays merge equal values, keeping the first occurrence and the source order. `opentype.names` is a raw view and is never merged.
- **Nothing is dropped by normalization.** Only exact duplicates are merged and non-standard forms are normalized. Fetched fields that were not selected are removed by `project.ts` alone.
- **Only keys present are handled, and a key the closure promised but the addon omitted throws.** Normalization never invents a default for a missing field.
- **Derivation follows the catalogue per platform.** A selected field is computed here exactly when it is selected but not in the closure; a field the platform provides itself (Windows `familyNames`) is normalized from the raw value.
- **Projection never edits a shared object.** It deletes keys of family and face objects only; a face's `opentype` and `axes` are shared between faces and hold selected entries only. It refuses to remove an `opentype` or `platform` entry.
- **Sorting is locale-independent**: families compare by `family.toLowerCase()` in UTF-16 code units, ties by the raw string. No `localeCompare`, so the order is the same on every machine.
- Errors from `getFamilies` and `getFamily` are promise rejections (the functions are `async`).
